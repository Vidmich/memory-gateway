{{- if not .Values.secrets.existingSecret }}

⚠  secrets.existingSecret is not set, so the pods have no DATABASE_URL, REDIS_URL, S3
   credentials, ENCRYPTION_MASTER_KEY or JWT_SIGNING_KEY, and will exit at startup with a
   configuration error naming the first one missing. Create a Secret whose keys are those
   variable names and set secrets.existingSecret to it. The chart will never create it for
   you: chart values are stored in the release and printed by `helm get values`, which is
   not a place for a master key.
{{- end }}

The first sign-in needs a superadmin, which is the one thing the UI cannot create:

  kubectl -n {{ .Release.Namespace }} run mg-seed --rm -it --restart=Never \
    --image={{ include "memory-gateway.image" . }} \
    --overrides='{"spec":{"containers":[{"name":"mg-seed","image":"{{ include "memory-gateway.image" . }}","args":["python","-m","app.cli","seed"],"envFrom":[{"configMapRef":{"name":"{{ include "memory-gateway.fullname" . }}"}}{{ if .Values.secrets.existingSecret }},{"secretRef":{"name":"{{ .Values.secrets.existingSecret }}"}}{{ end }}]}]}}'

Before the first real deploy, read docs/deployment.md — in particular the expand/contract
rule for migrations, which is what keeps a rolling upgrade from breaking the replicas that
are still serving the previous release.
